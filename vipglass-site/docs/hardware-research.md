# Фурнитура VIP Glass: публичные данные и проверка изображений

Актуальное правило: **артикулы, заводские коды, служебные обозначения отделок и точные ссылки на товар поставщика не публикуются и не входят в комплект для дизайнера**. Клиент выбирает понятный вид элемента и отделку в составе стеклянной конструкции. Отдельной продажи фурнитуры и цен на неё нет. Единственный публичный бренд — Pauli.

## Допустимый публичный контракт

| Поле | Что можно хранить и показывать |
|---|---|
| `id` | Нейтральный технический идентификатор вида, используемый для маршрутов и связей; не заводской код и не замена названию в интерфейсе |
| `title`, `intro`, `typeLabel` | Понятное русское описание вида, назначения и узла крепления |
| `applications`, `type` | Связь с существующими направлениями и группами; не обещание универсальной технической совместимости |
| `finishes[].id` | Нейтральный идентификатор отделки для фильтра и сохранения выбора |
| `finishes[].label` | Полное понятное название подтверждённой отделки, без кодов производителя |
| `finishes[].hex`, `effect` | Условный экранный образец цвета и поверхности; не колориметрические данные производителя |
| `image` и местный путь изображения | Файл с нейтральным именем по виду элемента; без номера модели в имени, alt, подписи или метаданных |
| `brand` | `Pauli` либо пустое значение |
| `notes`, `tags` | Подтверждённые пояснения и поисковые признаки без идентификаторов поставщика |

Не добавлять в клиентские данные поля `sku`, `articleNumber`, `articleCode`, `vendorCode`, `supplierCode`, `sourceBrand`, `sourceUrl`, названия заводских моделей и точные адреса исходных изображений. Запрет распространяется на HTML, CSS, JavaScript, JSON-LD, формы, значения, всплывающие подсказки, поиск и скачиваемые TXT/ZIP. Нейтральные ID допустимы для машинных связей в проекте; посетитель видит название, а не ID.

Фурнитура не выбирается отдельно в разделе зеркал. Выбор конструкции, характеристики зеркала и его оформления остаются в каталоге зеркал. Старые сохранённые пожелания и прежние адреса должны обрабатываться согласованно с актуальной структурой.

## Реальные изображения и отделки

Для фурнитуры используются только проверенные изображения конкретных реально существующих элементов из согласованных официальных каталогов. Генерировать фурнитуру, дорисовывать недостающий механизм или перекрашивать снимок под неподтверждённую отделку нельзя. Если точного изображения нет, позицию следует пометить для проверки, а не выдавать случайную иллюстрацию за товар.

Перед назначением изображения нужно подтвердить тип крепления, назначение, конструкцию и доступные отделки по одной и той же официальной карточке. Фотография одного исполнения не подтверждает все цвета серии. На самом изображении не должно быть артикула, стороннего запрещённого бренда или рекламного ценника; изображения с такими надписями не подставляются автоматически. Официальный каталожный рендер не называть фотографией выполненной работы VIP Glass.

Изображения сохраняются локально в `dist/assets/hardware-real/` с нейтральными именами. Отделки на клиентской стороне называются словами. Не переносить служебные сокращения из каталога поставщика. Толщины, нагрузки, размеры и совместимость не выводить как общие свойства класса без отдельной технической проверки конкретного изделия.

## Закрытая проверка источников

Исходная исследовательская привязка, точная модель, обозначение производителя, карточка изделия, оригинальный URL изображения, подтверждения отделок и дата проверки хранятся **во внешних приватных записях вне репозитория и архива передачи**. Эти записи нужны исполнителю для проверки соответствия и не являются содержанием сайта.

В `docs/exact-image-plan.json` для таких задач разрешено хранить статус проверки, нейтральный путь страницы и описание требуемого изображения. Конкретные ссылки и названия поставщиков из `hardwareSpec.supplierReference` исключены. Сохраняющийся статус `requires_current_model_photo_verification` означает задачу на проверку, а не подтверждение товара или фотографии.

Перед передачей комплекта повторно проверить новые файлы, старые сгенерированные HTML, экспорт проекта и документацию. Нельзя возвращать точные источники в публичный архив ради удобства дизайнера. После изменения исходников HTML пересобирается штатным сборщиком.
