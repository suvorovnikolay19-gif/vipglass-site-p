## 2. Состояние дерева до расширения

Прочитан `dist/other-trees.mjs`, объект `showers` на начало исследования: 4 верхние группы, 13 узлов-ветвей с корнем, 16 конечных моделей, максимальная глубина 4 при корне на уровне 0. Другой исполнитель может уже менять дерево; это снимок исходного состояния, а не проверка его последующих правок.

| Текущая группа | Конечные модели | Вывод |
| --- | --- | --- |
| `showers-open` | Один экран; экран с боковым возвратом | Полезная группа Walk-in, но возврат пересекается с угловым открытым экраном. |
| `showers-niche` | 4 распашные и 2 раздвижные схемы | Хорошая основа. Не хватает складного механизма, ясного состава неподвижных и подвижных полотен. |
| `showers-corner` | Дверь с одной/двумя боковыми плоскостями; открытый угол; трёхсторонний экран | П-образные ошибочно вложены в угловые. Нет углового раздвижного и складного семейств. |
| `showers-bath` | Перегородка, перегородка с дверью, отдельная дверь, дверь с боковым стеклом | Это остекление бани, не экран на ванну. Нужны разные название и код для ванны. «Перегородка с дверью» и «дверь с боковым стеклом» требуют проверки на дублирование. |

Конкретные пересечения: `showers-open-return` и `showers-corner-open-return`; `showers-corner-door-three-sides` имеет П-образную геометрию, несмотря на угловую родительскую группу; `showers-corner-open-wrap` также относится к трёхстороннему размещению.

## 3. Предлагаемые основные кластеры

Основной маршрут: **размещение → механизм → состав → карточка модели**. Глубина появляется из реального выбора, а не из промежуточных страниц с единственным потомком. Карточки групп должны показывать планы сверху, чтобы различия были понятны до чтения терминов.

| Группа / предлагаемый id | Подгруппы | Смысл различия |
| --- | --- | --- |
| Открытая душевая зона / `showers-open` | Прямой экран; экран с возвратом; два раздельных экрана | Вход остаётся открытым; пользователь выбирает расположение неподвижных плоскостей. |
| Душевая в нише / `showers-niche` | Распашная; раздвижная; складная | Стекло закрывает один проём между готовыми стенами. |
| Угловая душевая / `showers-corner` | Распашная; раздвижная; складная | Две стороны остекления; схема входа и состав различаются. |
| П-образная душевая / `showers-u` | Распашная; открытая композиция; другие механизмы только после отдельной проверки | Три стороны остекления возле одной стены. Это самостоятельное размещение. |
| Душевая со скошенным входом / `showers-trapezoid` | Одна дверь; две двери | Скошенная лицевая грань. «Трапеция» и «пятиугольная» — поисковые названия семейства, а не две автоматически разные модели. |
| Стеклянные экраны на ванну / `showers-tub` | Неподвижные; поворотные; раздвижные; складные; с торцевым стеклом | Установка на борт ванны. Существующая банная ветвь сюда не переносится. |
| Остекление бани / `showers-bath` | Стационарная перегородка; дверь; композиция с дверью | Сохранить отдельный пользовательский сценарий. Возможности душевого механизма нельзя автоматически переносить на баню/сауну. |

«Квадратная», «прямоугольная», «асимметричная» полезны как форма/пропорция плана внутри угловой или П-образной модели. Без изменения состава или механизма это не основание для отдельной карточки. «Без поддона», «чёрная», «матовая», «левая» — независимые признаки, а не соседи геометрии в основном дереве.

Отдельная модель оправдана изменением геометрии входа, состава секций, механизма или навески, влияющим на план и использование. Навеска стена–стекло и стекло–стекло может быть отдельной конфигурацией, когда действительно меняет схему. Цвет петли, зеркальное исполнение, произвольная ширина или один и тот же узел другого поставщика сами по себе не создают новую модель.

Для большого каталога нельзя механически перемножить семь групп, четыре механизма, цвета и стороны. Такой набор содержит неподтверждённые и дублирующиеся комбинации. Для расширения до десятков дополнительных моделей нужен реестр собственных схем: уникальный план, состав, механизм, навеска и подтверждённое семейство фурнитуры у каждой строки. По этим пяти источникам сам по себе целевой счётчик 65–90 не доказывает 65–90 разных конструкций.

## 6. UX карточки и навигации

1. **Название говорит о схеме.** Например: «Угловая раздвижная, одна дверь». Подзаголовок: «Два неподвижных стекла и одна подвижная створка». Внутренние коды не заменяют смысл.
2. **План сверху объясняет движение.** Неподвижные панели и двери различаются графически, стрелка показывает открывание, стены отмечены. Рядом интерьерный визуал для ощущения результата. План — собственная схема, не вырезка конкурента.
3. **Сначала решение, затем отделка.** Выбор стекла и металла не заставляет повторно проходить дерево. Левая/правая версия меняет схему в этой же карточке.
4. **Визуал соответствует модели.** Для раздвижной не использовать изображение распашной, для трапеции — обычного угла. Иллюстрация семейства фурнитуры не подтверждает конкретную комплектацию модели.
5. **Два способа входа, один канонический объект.** Пользователь может прийти из «Угловые» или фильтра «Раздвижные», но открывает одну модель с одним id. Walk-in с возвратом не дублируется в разных деревьях.
6. **Сравнение по делу.** Сравнивать 2–3 схемы по размещению, составу и движению двери. Не показывать неподтверждённые рейтинги надёжности или условные цены.
7. **Заявка сохраняет выбор.** «Рассчитать по моим размерам» передаёт модель, сторону, материал и отделку; запрашивает ориентировочные размеры, фото и город. Размеры пользователя — вводные для расчёта, а не производственный заказ без проверки.
8. **Пустые результаты объяснимы.** Не давать выбрать несочетающиеся фильтры; показать число вариантов и возможность сбросить один признак. Сохранять фильтры при возврате из карточки.

Для старых ссылок сохранить id там, где смысл модели не меняется. При переносе П-образных из угловой группы сохранить доступ к прежним id или задать явные соответствия. Открытый угол и экран с возвратом свести в одну каноническую схему после сравнения планов. Не смешивать `showers-bath` (баня) с новым `showers-tub` (ванна).

## 7. Ограничения источников

- ДушМастер повторяет артикулы и размещает одни изделия в нескольких группах; это не основание дублировать карточки VIPGlass.
- У StekloGlass встречаются похожие названия и противоречивые вспомогательные размеры. Числовую совместимость, ограничения и габариты в модель не переносить.
- У ProDush заголовок вложенной страницы иногда не совпадает с названием ссылки в каталоге. Проверять тело карточки и изображение перед использованием схемы.
- У LBspace встречаются чрезмерные и противоречивые утверждения о прочности, разрушении, царапинах и герметичности. Они не являются техническими основаниями для VIPGlass.
- Наличие душевой конструкции у конкурента не подтверждает доступность её механизма у используемых поставщиков. Особенно это относится к складным и нестандартным системам.
- Матирование, тонировка, закалка и марка базового стекла — разные свойства. Прозрачное неокрашенное стекло в публичном каталоге VIPGlass оставлено только CrystalVision по указанию пользователя.
