# Статические страницы и техническая основа каталога

`build-pages.mjs` формирует отдельный HTML-файл для каждого действительного адреса текущих деревьев каталога, услуг и материалов, разделов и карточек фурнитуры, а также общих страниц. Данные берутся из действующих модулей; дополнительного списка моделей, который нужно синхронизировать вручную, нет.

## Запуск

Из корня проекта:

```sh
node build-pages.mjs --check
node build-pages.mjs
```

Первый запуск только рендерит и проверяет страницы в памяти. Он не изменяет `dist` и не создаёт снимок шаблона. Второй после успешной проверки записывает страницы, `sitemap.xml`, `robots.txt` и `static-pages.json` в `dist`.

Перед первой записью исходный `dist/index.html` сохраняется в `src/shell.html`. Следующие сборки используют этот исходный шаблон, поэтому уже сгенерированная главная не становится оболочкой остальных страниц. Изменения общей HTML-оболочки после первой сборки вносятся в `src/shell.html`. Генератор не принимает сгенерированную страницу за исходный шаблон. При необходимости повторного снимка сначала нужно восстановить исходный `dist/index.html` с пустым `main`, затем удалить прежний `src/shell.html`.

## Содержимое результата

- Для `/catalog/...` записывается `dist/catalog/.../index.html`; для `/` — `dist/index.html`. Аналогично обрабатываются `/production`, `/materials`, `/hardware` и их действительные ветви.
- HTML основного содержимого, меню и подвала получает тот же рендерер приложения, который используется в браузере. Генератор выполняет участок `app.mjs` до регистрации обработчиков событий в изолированном VM-контексте с фактическими импортами приложения и пустым локальным проектом. Пользовательские сохранённые данные в сборку не попадают.
- Ссылки `#/...` преобразуются в чистые пути. Ссылки на старые `/solution/...`, старые группы, перенесённые душевые и `/production/materials/...` приводятся к действительным адресам. Для прежних адресов создаются совместимые HTML-файлы с содержимым целевой страницы и canonical на неё: прямое открытие и обновление старого адреса не зависят от наличия catch-all на сервере. Эти файлы не становятся дополнительными моделями каталога и не попадают в sitemap.
- `<base href="/">` сохраняет работу общих скриптов, стилей, изображений и шрифтов на вложенных адресах. Клиентское приложение остаётся подключённым для фильтров, конфигуратора и сохранения проекта.
- Каждая страница получает отдельные `title`, `description` и canonical. Заголовки и описания основаны на названиях, вводном тексте и контексте существующих ветвей. Контекст различает одинаково названные исполнения. Цены, наличие, сроки, отзывы и новые коммерческие утверждения не добавляются.
- JSON-LD содержит `BreadcrumbList` для внутренних страниц и `CollectionPage` с непосредственными дочерними страницами для ветвей. Остальные страницы имеют тип `WebPage`. Разметка `Product`, `Offer`, рейтинги и неподтверждённые свойства товара не создаются.

Canonical использует текущий адрес прототипа `https://vipglass.example`. У внутренних адресов завершающего `/` нет; главная обозначается `/`. В sitemap используется та же форма адресов. При смене домена нужно изменить `origin` в генераторе и значение домена в клиентском роутере.

`sitemap.xml` содержит только самостоятельные чистые адреса. Параметры фильтров, старые псевдонимы, `/project` и `/production/request` в него не включаются. Две последние страницы всё равно получают HTML для прямого открытия. Необоснованные `lastmod`, приоритеты и частота изменений не добавляются.

## Проверки и повторная сборка

До записи проверяются непустой рендер, отсутствие страницы ошибки, один `h1`, один `title`, один canonical, уникальность заголовков и описаний действительных страниц, сохранность запрета индексации, существование каждого внутреннего адреса и каждого локального ресурса, указанного в HTML и `srcset`. Совместимые старые адреса намеренно повторяют метаданные своей канонической цели. Обновление деревьев автоматически меняет набор страниц. Файлы удалённых маршрутов удаляются только по предыдущему манифесту и только при наличии отметки генератора; другие файлы `dist` не очищаются.

Повторный запуск на одинаковых исходниках даёт одинаковые файлы. Генератор не использует текущую дату и не изменяет модули приложения. Он проверяет наличие ресурсов, но не подменяет браузерную проверку интерактивности, проверку внутренних ссылок CSS или сетевую проверку опубликованного хостинга. Сервер должен обслуживать созданные вложенные `index.html` по соответствующим адресам; после размещения нужно отдельно проверить прямое открытие нескольких глубоких путей.

## Ограниченный доступ

На всех страницах сохраняется `<meta name="robots" content="noindex,nofollow">`. `robots.txt` содержит `User-agent: *` и `Disallow: /`. Это сознательная настройка закрытого прототипа; запреты не заменяют контроль доступа. Наличие HTML, canonical и sitemap не означает доступность для поисковых систем, индексацию или позиции в выдаче.

Открытие для индексации — отдельное решение после готовности публичной версии, проверки фактического домена и доступности сайта. Текущий генератор запреты не снимает.
