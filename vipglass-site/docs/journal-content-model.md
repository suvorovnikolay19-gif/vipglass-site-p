# Журнал, истории и Reels

Редакционный модуль прототипа VIPGlass. Данные: `dist/journal-data.mjs`; разметка и события: `dist/journal-ui.mjs`; стили: `dist/journal.css`. Маршруты, общая навигация и метаданные подключаются в оболочке сайта.

## Состав

- Три оригинальные полезные статьи: подготовка заявки, сравнение материала по образцу, планировка душевой.
- Два примера новостей, явно обозначенных как демонстрационные. Они не описывают реальные события компании.
- Шесть историй: три активные и три архивные.
- Три тематические подборки, по две истории в каждой.
- Один Reel с настоящим видеофайлом. Этот же демонстрационный ролик используется в одной истории; повторное использование обозначено в описании Reel.

Все изображения — существующие AI-визуализации проекта, а не фотографии выполненных объектов. Видео `/assets/content/demo-process.mp4` — немой иллюстративный монтаж; постер `/assets/content/demo-process-poster.webp`. Происхождение и проверка видео описаны исполнителем в `docs/demo-video.md`. Просмотры, лайки, отзывы, авторские цитаты и истории реальных заказов не придуманы.

## Данные

`journalArticles`: массив объектов `id`, `kind` (`useful` / `news`), `status`, `demo`, `publishDate`, `title`, `intro`, `readMinutes`, `topic`, `cover`, `sections`, необязательные `checklist`, `related`, `tags`.

`sections` — массив `{heading, paragraphs: string[]}`. Текст выводится с экранированием; произвольный HTML в статью не вставляется. `readMinutes` — редакционная оценка, не измеренное время посетителя.

`socialEntries`: массив историй и Reels. Поля: `id`, `kind` (`story` / `reel`), `status`, `archived`, `demo`, `publishDate`, `title`, `intro`, `topic`, `media`, `related`, `highlightIds`; у Reel также `description`.

`media` / `cover`:

- Изображение: `{type: 'image', src, alt, credit}`.
- Видео: `{type: 'video', src, poster, alt, credit}`.

`related`: `{path, label, intro?}`. `path` — внутренний путь каталога, материала, операции или формы задания без домена и без `#`. UI добавляет `#`, а общая оболочка нормализует адреса в обычные пути. Не использовать ссылки на удалённые агрегирующие разделы обработки.

`highlightCollections`: `{id, title, intro, cover, storyIds}`. Порядок `storyIds` задаёт порядок просмотра подборки. Поле `highlightIds` в истории должно соответствовать этому списку; проверка контролирует двустороннюю связь.

## Даты и состояния

Дата задаётся вручную в формате `YYYY-MM-DD`. Она форматируется без вычислений часового пояса. Текущая дата не удаляет историю и не переносит её автоматически в архив.

- История активна при `status: 'active'`, `archived: false`.
- Архивная история: `status: 'archived'`, `archived: true`.
- Статьи и Reels видимы при `status: 'published'`.
- `status: 'draft'` скрывает материал из публичных маршрутов и представлений.
- Подборка может объединять активные и архивные истории. Состояние исходной истории при этом не меняется.

Редактор сохраняет порядок элементов массива для обычной ленты. Для подборки порядок задаётся отдельно. Начальные даты относятся к демонстрационной коллекции; они не подтверждают даты событий компании.

## API и маршруты

`createJournalUI({esc, btn, crumb})` возвращает:

| Метод | Путь / назначение |
| --- | --- |
| `home()` | `/journal` |
| `articles('news', params)` | `/journal/news`, необязательный поиск `?q=` |
| `articles('useful', params)` | `/journal/useful`, необязательный поиск `?q=` |
| `article(id)` | `/journal/article/:id` |
| `stories('active')` | `/stories` |
| `stories('archive')` | `/stories/archive` |
| `stories('highlights')` | `/stories/highlights` |
| `story(id, params)` | `/stories/:id`; `?collection=:id` сохраняет контекст подборки |
| `reels()` | `/reels` |
| `reel(id)` | `/reels/:id` |
| `homepage()` | Блок статей и коротких форматов на главной |
| `bind(root, {navigate})` | События после вставки разметки, возвращает функцию очистки |

Неизвестный id возвращает `null`, чтобы оболочка показала общую страницу 404. Экспорт `journalRoutes` содержит `path`, `title`, `intro` для всех публичных страниц и подходит для сборки маршрутов и метаданных.

`bind` допускает отсутствие DOM и облегчённый DOM сборщика: без `addEventListener` завершается. Повторное подключение к тому же корню удаляет предыдущие обработчики через `AbortController`. Форма поиска использует переданный `navigate`; без него переходит через hash. Поиск выполняется по заголовку, аннотации, теме и тегам.

## Поведение и доступность

Просмотр истории — отдельная страница, не модальное окно. Есть явные ссылки назад, закрытия, предыдущей/следующей истории и счётчик позиции. Полоски прогресса являются ссылками; они показывают положение в последовательности, а не таймер. Автоматического переключения и автоматического воспроизведения нет. Стрелки клавиатуры работают вне управляющих элементов; клавиши видеоплеера не перехватываются.

Reels и видеоистория используют нативный `<video controls playsinline preload="metadata">`. Видео реально воспроизводится, перематывается и останавливается. Подпись сообщает об отсутствии звука. Ошибка загрузки открывает пояснение и прямую ссылку на файл; текстовый fallback доступен браузерам без поддержки video. Внутри видеокадра нет декоративной кнопки, имитирующей воспроизведение.

Содержание статьи работает через локальную прокрутку с фокусировкой раздела. Учитывается `prefers-reduced-motion`. Плеер не обрезает видеокадр (`object-fit: contain`). Иллюстративные фотографии на карточках могут кадрироваться; они не используются как производственный чертёж.

## Визуальные критерии

Сохранены цвета, шрифты и отступы существующего сайта. Большая фотография и спокойная типографика дают журналу редакционный характер. Статьи имеют удобную ширину текста, заметные подзаголовки и связь с каталогом. Истории выделены вертикальной композицией; просмотр — на тёмном фоне. На мобильном экране карточки, статья и viewer переходят в одну колонку. Стили ограничены префиксами `journal-`, `story-`, `reel-`.

## Проверка

`node validate-journal.mjs` проверяет наличие всех маршрутов и одного H1, состояния лент, последовательность подборок, ссылки предыдущей/следующей истории, поиск, экранирование запроса, демопометки, реальные медиафайлы и связанные пути каталога. Визуальную и интерактивную проверку встроенного в общую оболочку сайта выполняют после подключения root-модулем; модульная проверка HTML не заменяет браузерный просмотр.
