# Портфолио: данные, публикация и связь с каталогом

Раздел предназначен для фотографий, видео и согласованных отзывов по проектам. Сейчас настоящие работы не предоставлены. Шесть исходных записей имеют `isDemo: true`: в них использованы существующие AI-иллюстрации каталога и отдельный демонстрационный ролик. Названия относятся к примерам интерфейса; заказчики, адреса, даты, сроки и факты монтажа не придуманы.

## Модули и интеграция

- `dist/portfolio-data.mjs`: данные, нормализатор, фасеты, фильтрация и подбор по характеристикам.
- `dist/portfolio-ui.mjs`: `createPortfolioUI({esc,btn,crumb})` возвращает `home(params)`, `detail(id)`, `related(node,selected={})`, `homepage()`.
- `dist/portfolio.css`: стили с префиксом `portfolio-`. Подключается в общей HTML-оболочке.
- `/portfolio` — каталог; `/portfolio/:id` — опубликованная история. Фильтры: GET-параметры `product`, `color`, `kind`.

Роутер передаёт `URLSearchParams` в `home`. Форма имеет ID `portfolio-filter-form`, action `/portfolio`, method `get`, поэтому может работать и обычным переходом без отдельного обработчика. Для перехода внутри приложения обработчик формы может собрать `FormData` и вызвать общую навигацию.

Фотографии имеют кнопку `data-portfolio-image="/assets/..."` и подпись `data-portfolio-caption`. Общий обработчик открывает существующий лайтбокс по URL и подписи. Это отдельный контракт от `data-image` с ключами интерьерных изображений и `data-resource-image` с ключами производственных образцов.

Видео выводятся через настоящий `<video controls playsinline preload="metadata">` с `<source src>`, необязательным poster и подписью. Нужен прямой URL медиафайла, а не HTML-страница видеосервиса. Никакого autoplay или выдуманного видеопревью. Демонстрационный локальный файл `/assets/content/demo-process.mp4` создаётся основной интеграцией и подписан «Демонстрационный ролик».

## Формат проекта

```js
{
  id: 'project-slug',
  title: 'Название проекта',
  category: 'showers',
  kind: 'Открытая душевая',
  materialColor: 'Бесцветный',
  characteristics: {
    opening: 'Без открывания',
    glassCount: 1,
    geometry: 'Прямая плоскость'
  },
  productPaths: ['/catalog/showers/showers-open/showers-open-straight'],
  description: 'Описание с подтверждёнными сведениями об этом проекте.',
  cover: {src: '/assets/content/project-cover.webp', caption: 'Подпись'},
  stages: {
    before: {photos: [], videos: [], text: ''},
    during: {photos: [], videos: [], text: ''},
    after: {
      photos: [{src: '/assets/content/project-after.webp', caption: 'Подпись'}],
      videos: [{src: '/assets/content/project-after.mp4', poster: '/assets/content/project-poster.webp', caption: 'Подпись'}]
    },
    review: {photos: [], videos: [], text: '', author: ''}
  },
  published: true,
  isDemo: false
}
```

Пути в примере показывают формат; файлы `project-*` не входят в поставку. Для настоящего проекта `isDemo:false` выставляется только после замены демонстрационных материалов фактическими и проверки права публикации. Поля адреса, заказчика или географических координат не являются обязательными и не подставляются автоматически. Схематическая карта может хранить демонстрационные позиции отдельно, без объявления их адресами объектов.

`category` — один из существующих ID: `mirrors`, `showers`, `partitions`, `doors`, `stairs`, `canopies`. `kind` и `materialColor` — свободные непустые названия, одинаковые значения образуют общие пункты фильтров. Для связи и фильтрации предпочтительны единые названия цветов и видов.

`characteristics` — объект значений string, конечное number, boolean или массив таких значений. Он не ограничен нынешним набором характеристик: можно добавить форму, цвет зеркала, подсветку, раму, материал рамы, геометрию, число стёкол, движение двери, схему крепления, фацет и другие реальные особенности. Неизвестная характеристика участвует в строгом сопоставлении, даже если у неё пока нет отдельной подписи в таблице интерфейса.

`cover` — объект медиа или `null`. Редактор может требовать обложку для карточки. Сам нормализатор допускает запись без неё, когда есть фотографии, видео либо текст отзыва; карточка без изображения показывает нейтральное обозначение направления. Массив `productPaths` содержит только действующие пути каталога той же категории. Старый путь, зарегистрированный в `nodesByPath` как alias, нормализуется до канонического.

## Проверка и локальный черновик

`validatePortfolioProjects(value)` возвращает:

```js
{valid: true, errors: [], projects: normalizedArray}
// или
{valid: false, errors: ['Описание ошибки'], projects: []}
```

Ожидается массив объектов, до 200 записей. Проверяются уникальные slug-ID, обязательные названия, существующая категория, типы характеристик, корректность связанных путей, форма этапов и флаги `published`/`isDemo`. Некорректный массив не принимается частично. Неизвестные верхнеуровневые поля при нормализации не сохраняются.

Пустой массив допустим. Пропущенный `stages` или отдельный этап превращается в `{photos:[],videos:[]}`. Для этапа можно передать `{}`. У каждого этапа есть необязательный `text` (до 5000 символов, для отзыва — до 10000). Текст обычного этапа отображается как описание, текст отзыва — в соответствующем блоке. `author` поддерживается только у review; один автор без текста или медиа не создаёт блок. В каждом этапе независимо допускаются только фотографии, только видео, текст, их сочетание или отсутствие материала.

Медиа допускают локальные пути `/assets/...` и HTTPS-адреса. `javascript:`, `data:`, `blob:`, пути за пределами `/assets/` и обход каталогов отклоняются. Это проверка формата и допустимости адреса, не проверка наличия файла или его содержания. Для долговечной публикации загруженный файл должен получить адрес, доступный на сайте; временный blob URL из редактора в JSON не сохраняется.

`getPortfolioProjects()` читает массив из `localStorage['vipglass-portfolio-draft-v1']`. Корректный массив возвращается, включая записи с `published:false`; публичные методы интерфейса показывают только опубликованные. Корректный `[]` действительно очищает блоки портфолио. При отсутствии, недоступности или невалидности черновика возвращаются `portfolioExamples`. Прямой импорт и статический VM-рендер не требуют `document` или доступного localStorage.

Черновик хранится только в браузере. Он сам по себе не публикует новые страницы или файлы на сервере. Для постоянной публикации нужен перенос нормализованных данных в источник сайта и повторная сборка HTML.

## Фасеты и строгая связь с карточками

`portfolioFacetDefs` — массив объектов `{id,field,label,options}`. Опции имеют вид `{value,label}`. Направления берутся из каталога, актуальные цвета и виды — через `portfolioFacetOptions(def,projects)` из действующего набора проектов. `filterPortfolio(params,projects?)` применяет все заданные фильтры одновременно.

`matchingPortfolio(node,selected={})` возвращает опубликованные проекты:

1. Категория обязана совпадать.
2. Из `node.preset` берутся все заполненные характеристики, кроме служебных `title`, `note`, `mode`, `widthLabel`, `heightLabel`. Дополнительно учитываются `node.characteristics`.
3. Актуальный выбор можно передать плоскими полями `selected` или в `selected.characteristics`. Он заменяет соответствующие исходные значения карточки.
4. `selected.materialColor` (или `color`) и `selected.kind` проверяются по одноимённым полям проекта. При переданном `category`/`product` другая категория даёт пустой результат.
5. Каждая заданная характеристика обязана существовать в проекте и совпадать. Неподтверждённая характеристика не считается подходящей. Строки сравниваются после приведения регистра и пробелов; подстроки и приблизительные совпадения не используются. Для массива проверяется каждое запрошенное значение.
6. Только среди прошедших эти условия проектов явная связь в `productPaths` поднимает запись выше. Она не отменяет несовпадение цвета, фурнитуры или иной характеристики.

`related(node,selected)` возвращает пустую строку при отсутствии совпадений: не остаётся ни пустого заголовка, ни контейнера. При выборе другого материала или отделки фурнитуры основное приложение должно повторно вызвать этот метод с текущими характеристиками. Если новая характеристика не заполнена у демонстрационных проектов, их блок корректно исчезнет.

## Доступные состояния и композиция

| Demo ID | Наполнение | Что демонстрирует |
|---|---|---|
| `demo-round-mirror` | Одно фото «После» | Крупное одиночное изображение; пустые этапы и отзыв скрыты |
| `demo-open-shower` | Фото и видео во всех четырёх этапах, явно демонстрационный текст | Полная история; сетки с разным количеством медиа |
| `demo-bronze-mirror` | Два изображения «После» | Парная галерея и фильтр бронзового материала |
| `demo-clear-partition` | Иллюстрации в двух этапах | Частичная история без промежуточного этапа и отзыва |
| `demo-glass-door` | Только видео «После», отдельная обложка | Работа видеоплеера без обязательных фото этапа |
| `demo-glass-canopy` | Фото и демонстрационный текстовый блок | Отзыв без фото, видео и выдуманного автора |

Каждый демонстрационный проект и его карточка отмечены. На демонстрационной странице этап подписан как демонстрация блока; материалы не выдаются за последовательную съёмку одного реального объекта. Существующие AI-иллюстрации разных предметов используются для показа наполнения, а не как доказательство изготовления.

Внутренняя галерея сохраняет весь кадр через `object-fit:contain`; только обложки карточек используют ограниченную область предпросмотра. Одиночное медиа получает широкий формат. Два — пару, три и более — крупное первое медиа и последующую сетку. На узком экране медиа располагаются последовательно. Пустой этап не создаёт заголовок; отсутствующий отзыв скрывается целиком. Предусмотрены клавиатурный фокус, подписи, alt, управление видео и уменьшение анимации по prefers-reduced-motion.

## Границы проверки

Проверка модулей охватывает нормализацию, строгую фильтрацию и рендерирование разных состояний. Подключение маршрутов, лайтбокса, локального демонстрационного MP4, статической сборки и повторного подбора при изменении конструкции выполняется основной интеграцией. Публикация реальных работ требует настоящих материалов; эта поставка их не заменяет.
