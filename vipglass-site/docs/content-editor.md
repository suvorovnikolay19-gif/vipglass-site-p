# Редактор портфолио прототипа

Модуль `dist/content-editor.mjs`, стили `dist/content-editor.css`. Маршрут `/content-editor` подключает основной `app.mjs`.

Это демонстрация будущего управления контентом. Общего серверного хранилища, загрузки медиа на сервер, аккаунтов и публикации на сайте в модуле нет. На экране постоянно показано: **«Редактор прототипа — изменения только в этом браузере. Экспортируйте JSON для публикации».**

## Подключение

```js
import {createContentEditor} from './content-editor.mjs';
const contentEditor = createContentEditor({esc, btn, crumb});
// В маршрутизаторе:
main.innerHTML = contentEditor.page();
contentEditor.bind(document);
```

Добавить `content-editor.css` в shell. Все стили ограничены пространством классов `ce-*`; глобальные CSS, shell и app этот модуль не меняет. `bind(root = globalThis.document)` допускает переданный Document/DOM-корень и безопасно завершается, если DOM отсутствует. Повторное связывание одного host не добавляет повторных обработчиков. После сохранения отправляется DOM-событие `vipglass:portfolio-changed` с количеством проектов.

## Работа редактора

- Выбор существующего проекта, создание, дублирование и удаление. Дубликат получает новый ID и сначала скрыт в локальном портфолио.
- Название, категория, вид изделия, цвет, описание, видимость и признак демонстрационного материала.
- Обязательная фотография обложки для сохранения из формы; остальные фотографии и видео необязательны. Ссылки на видео могут иметь отдельный постер.
- Характеристики сохраняют типы: текст, число, логическое значение или массив. Это важно для сопоставления с каталогом. Названия характеристик должны совпадать с параметрами изделий.
- Выбор связанного изделия из текущей категории и список его точных путей. Смена категории не удаляет прежние связи молча: несовместимые пути нужно исправить перед сохранением.
- Этапы «До работ», «В процессе», «После работ», «Отзыв» включаются отдельно. Для каждого доступны фото, видео и описание, для отзыва также автор.
- Выключение этапа прячет поля, сохраняя их в текущей форме до сохранения. Если включить этап обратно, введённые данные остаются. После сохранения выключенный этап исключается; валидатор нормализует его в пустые массивы.
- «Сохранить в этом браузере» проверяет весь массив, записывает localStorage и обновляет предпросмотр. «Обновить предпросмотр» проверяет текущую форму и показывает результат без записи.
- Предпросмотр показывает только этапы с фотографиями, видео или текстом. Один автор без содержимого не создаёт секцию.

При переключении проекта с несохранёнными изменениями предлагается встроенное подтверждение. Несохранённые изменения формы не являются постоянным черновиком: перед уходом со страницы их нужно сохранить кнопкой.

## Хранилище и формат

Источник по умолчанию — `portfolioExamples`. Чтение и проверка делегированы `getPortfolioProjects` и `validatePortfolioProjects` из `portfolio-data.mjs`. Ключ localStorage: `vipglass-portfolio-draft-v1`.

Экспорт — массив проектов в файле `vipglass-portfolio.json`. Импорт принимает массив либо объект `{ "projects": [...] }`. Максимальный размер файла — 2 МБ; сами фотографии и видео содержатся в JSON только как ссылки. Модуль данных ограничивает массив 200 проектами.

```json
[
  {
    "id": "project-example",
    "title": "Название проекта",
    "category": "showers",
    "kind": "Открытая душевая",
    "materialColor": "Бесцветный",
    "characteristics": {"opening": "Без открывания", "glassCount": 1},
    "productPaths": [],
    "description": "Описание задачи и результата",
    "cover": {"src": "/assets/project-cover.webp", "caption": "Подпись"},
    "stages": {
      "after": {
        "photos": [{"src": "/assets/project-after.webp", "caption": "Результат"}],
        "videos": [],
        "text": "Описание этапа"
      },
      "review": {"photos": [], "videos": [], "text": "Текст отзыва", "author": "Автор"}
    },
    "published": true,
    "isDemo": false
  }
]
```

Это пример структуры, а не наличие указанных файлов. Для фото, видео и постеров допускаются только `/assets/...` или HTTPS-адреса без пользовательских данных в URL; проверку выполняет модуль портфолио. Временные `blob:`, `data:`, `javascript:`, HTTP-адреса и переходы `..` в локальных путях не сохраняются.

Импорт проверяется до записи и требует встроенного подтверждения замены. При ошибке JSON или данных текущий черновик остаётся прежним. Удаление и восстановление демонстрационных проектов также требуют встроенного подтверждения. Экспорт с несохранёнными изменениями предлагает сначала сохранить текущий проект.

`published` управляет показом в локальном портфолио и экспортируемом массиве. Это не запуск серверной публикации. Очистка данных браузера или другой браузер не сохраняют этот черновик; для переноса нужен экспорт.

## Проверка

Выполнена проверка синтаксиса Node. Изолированный Node DOM-harness `validate-content-editor.mjs` запускается командой `node validate-content-editor.mjs`, не требует пакетов и вызывает реальные обработчики редактора. Подтверждены:

- безопасный рендер и bind без глобального document;
- запись проекта и обновление предпросмотра;
- сохранность чисел, логических значений и массивов характеристик;
- исключение выключенного этапа, сохранность полей при выключении/включении до записи, сохранение описаний этапов;
- экранирование HTML в названии и отклонение небезопасного URL;
- отсутствие записи до подтверждения импорта, запись после подтверждения;
- создание действия скачивания экспортированного JSON;
- подтверждение и отмену сброса;
- сообщение об ошибке localStorage без замены прежнего массива.

Браузерная проверка не выполнялась. Попытка запуска средства браузерной проверки завершилась до запуска браузера; тесты ограничены Node и имитацией DOM. Порт локального тестового сервера после прекращения попытки не слушал.
